## Key concepts
- Two kinds of failure: server answered with an error vs. no answer at all
        - server answered is usually 4XX and 5XX errors
        - No answer at all means connection or timeout error
- What requests raises (and doesn't raise) for each
        - 4XX and 5XX errors are treated as a response, which does not raise an error.
                - use r.raise_for_status() to raise an error
                - try/except requests.HTTPError for error handling
        - No answer raises errors
                - requests.Timeout
                - requests.ConnectionError
- Why always pass timeout=
        - ensures we don't wait on requests that never respond
- What to retry and what not to
        - retry idempotent calls
        - only retry transient failures: timeouts, connection errors, 429/502/503/504
        - never retry 404/400 — they fail the same way every time
- Why only idempotent methods get retried
        - Ensure that we don't change the server's state over and over again without knowing
        - EX
                - might call POST multiple times, creating new resources in server without knowing
- Exponential backoff
        - Retry with a exponential wait time each retry
        - ensures we don't overload server with request calls
