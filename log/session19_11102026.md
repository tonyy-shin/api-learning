## Warm-up (concept questions)
1. Why an error body needs a code when the status is already 422
   - Mine: the code tells you why it failed
   - Missing piece: a program can branch on the code (e.g. highlight the rating box on invalid_rating); one status covers many failure cases
2. Why r.json()["title"] crashed on a 500
   - Mine: request was fine, server failed, sends an error body
   - Missing piece: the status tells you which body shape you got; "title" only exists in the 200 shape, so check status first
3. Why OpenAPI uses one shared Error schema via $ref
   - Mine: otherwise each error looks different
   - Missing piece: one source of truth; change it once, every endpoint updates; copies drift apart
4. What load_dotenv() does, and why NASA sends 403
   - Mine: loads keys from .env; 403 because no key
   - Correction: load_dotenv copies .env values into the process environment; without it os.getenv returns None
   - 403: request is well-formed (not 400) and the server is fine (not 500)
   - Don't retry: same request gets the same 403; retry only when waiting could fix it (429, 503)

## Takeaways

- Retry only if waiting could fix it
- Server-calculated fields are read-only
- 404 = something you referred to doesn't exist, not just the URL
