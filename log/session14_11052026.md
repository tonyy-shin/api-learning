## What I learned
- Start with resources, their fields, and how they connect before writing endpoints
- "Belongs to" means a resource has one parent, stored as a field like coach_id
- "Has many" is the same connection from the parent's side
- The server sets id. The client sends the other fields unless the URL already provides them
- Use one level of nesting at most
- Use nested paths to list or create children: /coaches/42/reviews
- Use direct paths for one item: /reviews/7
- A breaking change makes existing client code stop working
- /v1 is the API version. It lets existing clients keep their format when /v2 is released
