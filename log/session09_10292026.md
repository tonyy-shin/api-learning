## Warm-up
1. A 503 error is when the server is not ready to handle the request. So, it can be retried.
2. When the server never answers, it gives a Timeout exception.
3. A 404 error needs to be raised for status to get an exception.
4. A 429 error is when you sent too many requests too fast and hit the rate limit. So, it is probable that a retry will work.


## What I learned
- A 429 error can retried.
- Pagination
        - offset -> where it should start sending the resource
        - limit -> the amount of resource it should send (add limit to offset after request)
        - Page number -> same thing as offset/limit pagination but with pages
        - Cursor -> Cursor on specific item so it doesn't skip over added items (makes over offset/limit weakness)
                    Big API's prefer cursor pagination
        - Offset/Limit Pagination
                - count: total number of items
                - previous: url to previous call 
                        - "https://pokeapi.co/api/v2/pokemon?offset=0&limit=5" with the full offset&limit
                        - None on first page
                - next: the response gives the next url with updated offset and limit(limit stays the same)
                        - None if there is no next
                        - make the loop until next hits None
