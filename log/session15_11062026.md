## What I learned
- Single item: send the object itself
- List: wrap it as {"data": [...], "count", "next", "previous"}
- The wrapper makes room for metadata, and adding keys later isn't a breaking change. Switching from a bare array to an object would be
- 201 on create returns the full created resource, including the id the server set
- The request body leaves out id (the server sets it) and coach_id (the URL gives it)
- Every error uses one shape: {"error": {"code": "...", "message": "..."}}
- 400: the server couldn't read the request (broken JSON)
- 422: the request was readable, but the data broke a rule (missing field, value out of range)
- The server checks the rules and rejects bad data. It doesn't store whatever it receives
